## 1. Цель документа

Документ фиксирует, что стоит добавить или улучшить в проекте, чтобы повысить стабильность, удобство, управляемость учебного процесса и готовность системы к реальной эксплуатации.

Приоритеты:

| Приоритет | Значение |
| --- | --- |
| P0 | Критично: влияет на доступность тестов, сохранность данных, безопасность или блокирует основной сценарий |
| P1 | Высокий: заметно улучшает основной учебный процесс и снижает количество ошибок пользователей |
| P2 | Средний: повышает удобство, прозрачность и скорость работы |
| P3 | Низкий: полезное развитие, polish, расширения и автоматизация |

## 4. Критерии качества для новых задач

Каждая новая задача из roadmap должна проходить минимальный чек-лист:

| Критерий | Требование |
| --- | --- |
| Backend | Есть проверка прав доступа и единая бизнес-логика, без дублирования условий в разных endpoint-ах |
| Frontend | Есть загрузка, пустое состояние, ошибка, disabled-состояния и понятные причины недоступности |
| Данные | Состояние не ломает существующие попытки и не требует ручной правки БД |
| Тесты | Есть backend-тест или Playwright-сценарий для основного пользовательского пути |
| UX | Пользователь видит, что произошло, что доступно и что нужно сделать дальше |
| Безопасность | Студент не получает ответы, чужие данные и недоступные дисциплины через API |
